## 问题记录

### 1. 外部清空队列后 Dashboard 仍显示缓存的空队列

- 严重度：P2
- 位置：`qtask_list/admin.py:91-121`
- 复现：Dashboard 已运行并发现过旧队列时，通过另一个进程批量删除 Redis 队列和历史；Dashboard 的 `/api/queues` 仍返回此前发现的队列名。本轮观察到 Redis 注册表为 0，但界面/API 暂时显示 7 个空队列。
- 实际结果：`queue_names()` 每小时才重新扫描旧版队列；扫描结果保存在进程内缓存。外部清理不会同步清除此缓存，重启 Dashboard 后列表才恢复为空。
- 影响：操作人员可能误以为仍有队列，无法从界面确认“已从 0 开始”。Redis 中的数据实际已删除。
- 建议：让删除/批量清理操作能失效该缓存，或避免在注册表为空时返回已过期的旧发现结果；补充“Dashboard 运行期间由外部清理”的回归测试。

### 2. 普通关键词搜索会额外请求任务详情并产生 404

- 严重度：P3
- 位置：`qtask_list/frontend/src/pages/TasksPage.tsx:38-46`
- 复现：在任务搜索中输入 `browser_test_dlq` 这类长度至少 8、仅包含字母/数字/下划线/连字符的普通关键词。
- 实际结果：页面正确执行关键词搜索，但同时将该词当成 `task_id` 请求 `/api/task/browser_test_dlq`，浏览器控制台记录 404。本轮该请求出现 2 次。
- 影响：搜索结果不受影响，但产生无效网络请求和控制台错误；符合当前正则的 action 搜索都会触发。
- 建议：将精确 ID 自动打开限制为实际 task_id 格式（例如 UUID），或改为用户明确提交后再查询详情。
