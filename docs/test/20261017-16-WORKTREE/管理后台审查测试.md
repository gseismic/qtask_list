## 额外 API 复现

根目录执行：

```bash
uv run --no-project python docs/test/20261017-16-WORKTREE/review-management-cases.py
```

执行完成，结果见 [review-management-results.json](./review-management-results.json)。该脚本后续复跑会为结果文件追加数字后缀，不覆盖已有结果。表中预期表达管理员可观察的正确行为；实际结果是本次观测，并非产品验收通过。

| 场景 | 预期 | 实际 |
| --- | --- | --- |
| 删除清空后 Worker 登记并领取 | 活跃任务受到保护，删除应拒绝或与登记/领取串行化 | 删除返回 200；心跳、processing、历史全部消失；已领取消息 ack 返回 False |
| 删除状态键后并发投递 | 消息、历史与注册信息保持一致 | 投递被接受，ready 留有 1 条消息，但历史和队列注册项被删 |
| 501 条 ready，limit=500 | 有继续查询剩余记录的入口 | 队列接口没有 next_cursor/has_more；全局分页接口对同队列返回有效 next_cursor |
| 5001 条不匹配历史，ready 加时间筛选 | 返回有界、可继续查询的页面 | 队列接口 500；同条件全局接口 200、scan_limited=true、has_more=true |
| 正常 V2 ready/processing 列表 | 保留已有的时间和执行元数据 | 列表没有 created_at/updated_at/max_attempts；详情记录包含这些字段 |
| max_attempts=1 的失败任务经 Dashboard replay | 重试预算不应无提示改变 | 新任务 max_attempts 变为 3 |
| 对同一个无 logical_key 的失败任务 replay 两次 | 父任务仍可追踪两个新实例 | 两次均 accepted=true，但父记录 replayed_by 只保留第二次 ID |
| 执行截止已过的 DLQ 批量 replay | 明确反馈未处理原因或要求新截止 | 200、moved=0；原 DLQ 仍有 1 条任务 |
| 合法队列名含 `/` | 管理接口与队列库的命名范围一致 | 入队和注册成功，路径型队列 API 均 404；全局 query 参数搜索能找到任务 |
| 中文密码或中文用户名 | 正确凭据可登录，错误输入返回受控 4xx | 两种正确凭据均导致登录 500 |
| 查询第一页后删除该页任务，再续游标 | 仍存在的其余记录可全部访问 | 三条记录、每页一条时漏掉一条，且返回 has_more=false |
| Redis 内存高于 maxmemory | 监控状态或未启用告警状态表达实际配置 | 1,049,680 字节 / 524,288 字节仍返回 healthy；Dashboard 的 threshold_mb=None |

并发场景通过在两个真实 Redis 操作之间插入实际登记、投递或领取来确定性复现交错，没有用伪 Redis 替代状态操作。Worker 用例已完成真实 pop_claim_no_wait，但未执行任何业务 handler；其 ack 失败用于验证 processing 已被删除的后果。

另确认服务端 CORS 会接受任意 Origin 的预检及无认证 POST。但本次 Chrome 从模拟公网 HTTPS Origin 到 loopback 的请求被浏览器阻断，不能据服务端响应认定公网网页已成功利用；未将其列为已确认可利用漏洞。
