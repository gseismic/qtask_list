## 目的与范围

按用户要求，从清空后的状态重新完整检查管理后台。覆盖总览、队列、队列详情、任务列表、任务详情、Worker、告警和教程；逐页操作当时可见的按钮、筛选器、菜单及确认弹窗。队列操作、任务详情、Worker 恢复等条件操作使用本轮临时数据触发。测试结束后删除本轮创建的数据，并核对 Dashboard 和 Redis 均为空。主页面最终状态截图为[主页面截图](./主页面.png)。

## 环境准备与执行步骤

Dashboard 启动命令：

    python -m qtask_list.cli dashboard --host 127.0.0.1 --port 8766 --no-open

浏览器操作通过 Playwright CLI 会话 qtask-full 完成。先打开测试地址并保存页面快照，再按页面执行导航、点击、输入、选择筛选项和确认弹窗；页面快照以 YAML 文件保存在本目录。步骤如下：

1. 在 Redis localhost:6379/0 准备带有 ready、processing、retry、DLQ、delay、历史记录、失联 Worker 和告警状态的临时队列与任务。
2. 从总览开始，按侧边栏逐页操作各可见控件；对清空、删除、恢复、重放等有副作用的操作，分别检查取消路径和确认路径。
3. 对需要特定状态才能显示的按钮，先用临时数据生成对应状态，再执行操作并检查 UI、API 和页面快照。
4. 保存总览空状态及危险操作确认等截图，并保存各页面关键状态的 YAML 快照。
5. 清理 codex_browser_20261016 前缀下的临时数据，刷新页面并扫描 Redis 相关注册表、历史、任务、Worker 与队列状态键，确认清理结果。

## 问题与失败

本轮确认两项待修复问题，均在测试基线 8cea280c9007d4e924d5705632c6685a80d53da1 上复现：

1. **P2：外部清空后 Dashboard 暂时显示已删除的队列。** Dashboard 进程缓存旧版队列发现结果；Redis 注册表为空时，API/界面仍曾显示 7 个空队列。重启 Dashboard 后显示恢复。详情见 [KI-20261016-1218-001](../../known-issues/KI-20261016-1218-001-queue-discovery-cache.md)，复现截图为[缓存异常复现](./缓存异常复现.png)。
2. **P3：普通关键词搜索额外请求任务详情并产生 404。** 搜索 browser_test_dlq 时页面同时将关键词作为 task_id 请求详情接口，本轮记录到两次 404；关键词筛选结果仍正常。详情见 [KI-20261016-1218-002](../../known-issues/KI-20261016-1218-002-task-search-id-heuristic.md)。

## 清理与验收

测试结束后，Dashboard 的队列列表为空，主页面显示“还没有任何队列”。Redis 核验结果：qtask:queues 为 0，qtask:hist:*、qtask:task:*、qtask:workers:*、*:processing、*:processing:*、*:retry、*:dlq、*:delay 均无本轮残留数据。浏览器在清理完成后未记录新的控制台错误；主动复现普通关键词搜索问题时记录到上述两次 404。
