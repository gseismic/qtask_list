## 循环复核新增确认与修复

1. 同分数 ID 的 Lua 默认比较受 locale 影响，改用明确的字节序；Unicode/NUL ID 不遗漏。
2. 孤立 V2 消息不能降级为旧格式重放；失败时保留原 DLQ 和描述符。
3. 行 Enter 的默认动作会落到刚自动聚焦的关闭按钮，已阻止默认动作；[修复前证据](./modal-enter-before-fix.txt)与最终核心浏览器结果对应。
4. 旧 HTML 缓存会请求已被构建移除的 hash 资源，SPA HTML 增加 no-cache；HTTP 回归通过。
5. 登录网络失败原先没有反馈，且可能重复提交，已补反馈与重试恢复；[修复前证据](./login-network-before-fix.txt)、前端单测和真实登录浏览器均覆盖。
6. 新 Starlette 下旧 TemplateResponse 参数顺序报错，改为关键字调用；[失败安装记录](./clean-install.txt)保留，最终干净启动通过。
7. Redis/外存异常原先可能暴露原异常或失去反馈，统一受控去敏响应；前端拒绝无效 JSON 成功响应。
8. DLQ 快照取出后若被另一操作移走，原实现会从历史再次生成任务。新增显式 `require_dlq`，在 replay Lua 原子检查原消息；[修复前竞争回归](./dlq-race-before-fix.txt)失败 2 项，最终全量通过。覆盖快照之后、Lua 之前两种确定性交错；单项 DLQ 返回 409，历史主动重放仍可使用。
9. 测试服务器被 SIGTERM 终止后旧清理逻辑未生效；修复手工脚本信号处理，真实子进程退出 0，Redis/socket/临时目录均清除，见[清理结果](./resource-cleanup-2.json)。

同目录内不带 final 或带较小数字后缀的文件保留中间状态，包括产品缺陷复现、测试驱动错误及修正过程。空的 `resource-cleanup.json` 来自中断的第一次清理探测，不作为通过证据；以本记录链接的最终日志为准。失败记录未被覆盖，亦未被计为最终通过。
