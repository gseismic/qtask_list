| 过期的 skipped 等终态无法重放 | failed/skipped/cancelled 的已过期截止可在确认弹窗内更新后调用 replay；待处理过期视图调用专用接口，明确说明旧任务会被取消。验证原 skipped 终态保留、payload 保留且产生新任务。 |
| ID 直达状态为空、旧提示覆盖新状态 | 统一从最新 outcome/location/delay_reason/deadline 推导状态，列表提示只回退旧记录。直接打开执行中任务显示执行中，并移除删除入口。 |
| 旧分页响应混入新筛选 | 公共 `useTaskPage` 隔离查询代次和请求序号；翻页取消该列表自动刷新。延迟旧“全部”分页响应，切到 DLQ 后释放，仍只有正确的 1 条死信；多页列表在全局轮询时保持稳定。 |
| completed 提供无效重放 | 按后端契约限制 replay；completed 和缺少可还原参数的旧记录不显示 V2 replay，保留旧 DLQ 重入队。 |
| 空闲被算入停滞 | 采样记录可消费积压是否持续，空闲、无 Worker、完成进展、长观测中断重置；未知指标保持未知。时钟回归验证新积压不误报，连续积压满两分钟才提示。 |

| 错误落在确认弹窗背后 | 共用确认弹窗接收操作错误和详情刷新错误；失败在当前弹窗可见。忙碌时阻止背景关闭，处理提交失焦后的 Escape 与焦点恢复。 |

## 体验优化

1. 总览新增 namespace 与队列名筛选，KPI 对应当前范围；保存筛选与折叠，健康组默认收起，异常组默认展开，正常队列按名称稳定排序。使用 105 个队列验证分组与过滤。
2. 采样移到应用层，SPA 导航保留；浏览器验证离开总览进入队列再返回，无需重新等待 30 秒。色条改为当前排队、执行、延迟、旧 retry 的同一时点构成，观测完成量独立展示。
3. 重放成功提供新任务跳转，来源与多次重放血缘均可点击；支持逗号文本和旧 JSON 数组。结果 `false` 不再被当成缺失。
4. 合并全局和单队列任务列表逻辑，高级 action 与发布/完成时间筛选一致；全局查询条件保存在地址中，浏览器重新加载仍保留。单队列详情移除重复状态下拉，时间条件渐进展开。
5. 请求失败保留同查询的缓存与成功更新时间；重试尚未成功时继续标记过时。局部筛选仍显示全局 Redis 内存告警。浏览器存储不可用时，主题与偏好安全降级，告警写入失败明确提示。
6. 修复路由参数再次解码导致字面 `%2F` 名称错误；区分累计结果计数与当前保留的可查询记录，避免累计量被解释成查询总数。
