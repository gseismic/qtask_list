## 第二轮复查扩展

- 首轮修复后全量 169 passed，ruff、mypy 均通过。
- 增加 begin 已提交但响应丢失、`max_attempts=1` 的回归：未准入 handler 的领取恢复应返还预算，已准入 handler 的异常退出保留已消耗预算。
- 历史 Hash 不能对 action/logical_key/trace_id 等文本字段盲目 JSON 解码；统一字段解码供 History/Admin/Archive 复用，并保留旧布尔结果。
- 重放与普通投递采用相同提交确认语义；补充 Lua 计数值格式预检、恢复 deadline 索引、停止期间内部跳过循环的响应性等相邻中断窗口验证。
- 身份键迁移复查：新前缀必须完全位于旧明文键空间之外，旧终态 String owner 转换后仍保留原 TTL 与终态；补充管理整队删除及保留期回归。

## 第三轮复查扩展

- 第二轮修复后全量 188 passed，ruff、mypy 均通过。
- 区分未准入 handler 的 begin 响应丢失，与已经发生过外存读取失败但未确认结算的情况；后者必须保留已消耗预算，不能重新退款后多次下载。
- 补查客户端时钟超前导致无延迟任务错误进入 delay；普通投递与重放按 Redis 时间及显式 not_before 判断可用性。
- 旧格式无效 action、非有限/低于 Redis 毫秒精度的租约配置应在状态转换前明确拒绝，避免留下无法完成的循环。
- 旧历史转换与读取并发时存在 TYPE/GET 两步竞态；History、Admin 批量读取、Archive 改用单键原子快照读取，转换操作同样从快照执行 CAS，并补充竞争回归。
