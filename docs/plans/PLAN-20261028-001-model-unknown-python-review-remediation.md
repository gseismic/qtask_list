## 设计复核补充（2026-10-28 17:37）

完整接口与并发设计见 `docs/design/python-review-remediation-20261028-overview.md`。

- Worker 身份需要 Redis 中带随机实例令牌的原子占用、续租与条件释放。保持现有 heartbeat 时间值供管理端读取；只有当前令牌持有者可删除心跳或 Worker 注册。冲突应显式失败，租约失效后仍遵循既有 at-least-once 语义，不能声称外部副作用严格互斥。
- 自动 stale 恢复只处理 Worker 注册表中的 processing；没有心跳契约的自定义消费者保留给明确的管理操作，管理端须说明无法自动判断其生死。
- Dashboard 默认只允许同源浏览器访问；限制 CORS 预检本身不能阻止无预检 POST，因此还需校验带 `Origin` 的状态修改请求。确有跨域集成时以显式允许列表配置，不改变无 `Origin` 的非浏览器 API 客户端。
- 新版任务预算由生产端写入任务实例；Worker 配置用于本 Worker 自身投递或旧消息迁移，不能悄悄覆盖已经持久化的预算。按核实结果修正公开说明并增加覆盖。
- 对跨 SQLite/Redis 归档，只有 Redis 原始快照未变化时才删除；并发更新时保留更新后的记录或写入包含更新的后续快照，不丢失重放血缘。
- 复核发现自定义 processing 还影响删除、手工恢复和键空间归属。默认管理操作不得把无心跳消费者当成已停止；需要显式确认的入口才允许清理其 processing。登记时检查与现有队列及 Worker processing 的冲突，后续新队列也不得占用已登记的自定义 processing 键。
- Worker 失去令牌时可能仍有阻塞领取正在返回；仅在心跳检查令牌不足。领取开始及本地遗弃消息恢复也需在 Redis 原子校验令牌，失权后退回尚未开始的消息并停止旧实例。

## 外存清理复核补充（2026-10-28 18:13）

继续检查 RemoteStorage 的 TTL 清理时，发现保留期元数据读取失败被当作无保留期，且清理与保留期延长可以并发；这可能删除仍需保留的文件。先用隔离目录复现，再让写入保留期与 TTL 清理在共享目录上串行化，元数据不能解析时保守保留，并使用原子替换避免读取半写入内容。验证损坏元数据、并发延长和清理、正常到期清理及现有外存 GC；锁失效或不可用时须保留文件并报告错误。

继续复核本机无 token 外存服务的浏览器边界：multipart 上传不需要跨域预检。先验证跨来源网页是否能写入；若能写入，在服务端对携带 Origin 的写请求核验同源，并保留无 Origin 的 SDK 客户端访问。
