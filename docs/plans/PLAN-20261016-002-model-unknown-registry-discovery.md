## 已确认事实与方案

- enqueue/replay 的状态脚本已登记 qtask:queues；目前 Worker 心跳只登记 Worker，空队列启动的消费者可能没有队列注册项。
- Worker 退出目前无条件删除 Worker 注册项；取消旧扫描后，残留 processing 需要通过注册项继续可见。
- 队列与 Worker 的全局发现目前包含旧数据扫描和进程缓存；上一任务额外增加了缓存存活校验。用户取消兼容要求后，这些复杂度均可删除。

选择注册表作为唯一来源，避免用存储键推测队列存在。Redis 的空 List/ZSET 不保留键，仅检查真实状态键会隐藏正常空队列；继续扫描或补建旧数据注册项会保留不必要的兼容复杂度。因此不做这两类推测或自动迁移。

Worker 心跳通过新 Lua 脚本原子登记队列、Worker 和 TTL 心跳；写入前检查三个键的类型、TTL 和队列 namespace 冲突，避免部分登记及并发冲突。Worker 退出删除心跳；仅在没有 processing 时移除 Worker 注册项。有残留任务时由 list_workers 显示失联，恢复完成后清理注册项。

失效 Worker 的注册项清理也原子复核心跳及 processing，避免在观测为空之后与并发续租交错，误删刚续租的注册项。
