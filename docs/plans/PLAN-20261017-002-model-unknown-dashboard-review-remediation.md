## 设计与取舍

使用 `api-design-zh` 复核管理者场景、操作范围、失败语义和并发约束；React 使用 `vercel-react-best-practices`，工具沿用 uv/pnpm，浏览器使用独立 Playwright 会话。

1. **删除**：比较跨全部写路径的维护锁与单次 Redis 原子删除。采用后者，在同一 Lua 中校验 namespace/类型、复核心跳、收集并删除所属数据、安排专属外存回收和注销。Redis 串行化使投递/登记发生在删除之前或之后，避免锁租期过期及逐个领取路径改造。清理前完成验证；大队列原子操作的阻塞风险需衡量和记录。
2. **分页**：历史查询以创建时间和 ID 为稳定边界，替换可变 offset；同分数 ID 必须能够完整续页。保留固定查询队列集合、截止时间、扫描预算和精确 ID 定位。容器读取必须提供完整分页协议，并保持无历史消息的可诊断性；不得仅以 500 条截断掩盖剩余数据。
3. **数据与命名**：共用任务行语义，补充 location、时间和执行字段；合法队列名称和任意字符串任务 ID 必须可以在 HTTP 中无损寻址。采用明确的查询参数入口承载名称/ID，保留现有路径入口的可用性，前端调用、手工回归脚本与 API 测试同步。历史记录按稳定位置续页；原始无索引容器作为诊断补充，内容变化导致其续页位置不再可靠时明确要求刷新。
4. **重放**：管理后台默认继承原任务执行预算；库显式配置继续清晰表达调用方意图。原任务血缘追加全部新实例；批量操作返回已处理、跳过及原因并在当前操作上下文展示，部分失败不能伪装成全量完成。
   复核补充（2026-10-17 17:46）：DLQ 快照取出后消息可能已被另一操作移走；不能再按历史记录无条件生成实例。SDK/Admin 的 `replay_task` 增加显式 `require_dlq`（默认 False），DLQ 单项/批量入口固定启用；在既有 replay Lua 中以原消息的 LREM 成功为创建前提，消息缺失时受控拒绝或计入跳过。历史主动重放仍允许重复操作。
5. **监控与认证**：Dashboard 支持明确的内存阈值，未指定时按已配置 maxmemory 监测；两者均未配置时显示未启用，避免“正常”误导。凭据使用 UTF-8 bytes 常量时间比较，跳转必须经 URL 解析确认同源。
6. **模态**：抽屉、投递、确认及诊断统一焦点进入、Tab 限制、嵌套层级、Escape、忙碌保护与焦点恢复，避免背景获得键盘操作。
