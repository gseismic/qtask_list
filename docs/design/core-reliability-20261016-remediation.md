# 核心可靠性修复设计

- 创建时间：2026-10-16 07:46（Asia/Shanghai）
- 执行模型：Codex（环境未提供具体模型 ID）
- 基线：20b4b594c107d2390c4b157d5ff88722458bc87f（此前 00c5a82 的核心审查结论仍适用）
- 范围：全部非 UI 核心及管理入口；依据上一轮已复现的 11 项缺陷。

## 场景与不变式

需要覆盖普通 JSON 投递、历史任务兼容、外存暂时故障、Redis 领取/结算故障、同键串行、DLQ 巡检修复、归档、精确版本替换和业务身份去重。

1. handler 接收到的 JSON 值与投递值一致，包括空数组、64 位整数和浮点数。
2. 投递报错不得返回成功；类型错误应在 Lua 写入之前发现。
3. 已开始 handler 的任务在结算确认前保持本地所有权和续租；领取中断产生的无人处理消息可在当前 Worker 内恢复。
4. 续租周期必须短于 heartbeat 与并发 lease 两种有效期；停止期间维持已有 drain 契约。
5. 样本缺失只能标记为未知，不能作为删除或修复 operational 标记的依据。
6. V1、旧 String 历史和现存 V2 均可读取、消费、重试和管理；外存读取同样受总 attempt 预算约束。

## 方案比较与裁决

| 问题 | 备选 | 裁决及原因 |
| --- | --- | --- |
| JSON 无损 | 新信封/新 payload kind；全部压缩；Python 序列化消息模板、Lua 仅填运行字段 | 采用模板：保留现存 V2 inline/zstd/external 格式，也修复现存待消费信封，无须改 UI |
| Redis 故障恢复 | 故障即退出；周期恢复全部 processing；保持结算重试并恢复未登记消息 | 采用第三种：结算不重新执行 handler；恢复只处理当前 Worker 中未被本地 claim 保护的消息 |
| 键冲突 | 迁移全部 operational 键；一律禁止状态名称；按注册队列核验实际冲突并预检类型 | 采用实际冲突核验：合法独立命名继续可用，只有与已注册队列的状态路径重叠时拒绝；投递与注册核验在同一 Lua 中完成 |
| dedup 兼容 | 旧哈希/明文继续混用；版本化 owner 前缀并迁移旧 owner | 采用版本化 owner；按旧键类型和 logical_key 核验迁移，避免哈希字符串与明文相撞 |
| V1 外存重试 | 单独维护下载预算；下载前迁移到现有 V2 descriptor | 采用先迁移：保留旧压缩/外存引用，用兼容标记处理旧 `_retry` 与延后获取的 action；复用统一状态机 |
| 旧历史 | 每个调用分支临时处理；统一 CAS 转 Hash | 采用统一转换，保留 TTL、嵌套 JSON 和终态字段，避免各入口兼容行为分叉 |

## 接口与兼容

- 公开任务接口保持 `TaskSpec`、`enqueue`、`ack/fail` 和 `QueueAdmin` 现有形态。
- 内部增加无损运行消息模板、历史格式转换、无人处理 claim 恢复和结算重试辅助函数。
- 队列名称的内部前缀、glob 字符和实际状态路径冲突在 README 明确；不对已有冲突队列做破坏性自动迁移。
- dedup 新前缀为 `qtask:owner:v2:{sha256(queue)}:{sha256(logical_key)}`，完全位于旧明文键空间外；兼容迁移须在生产者、消费者统一更新后使用，不承诺旧版本写入方理解新身份键。
- supersede 整数按有符号十进制字符串精确比较，字符串版本沿用字典序。
- 归档结构化字段显式编码为 JSON；维护指标失败不能杀死维护线程。

## 三轮设计自查

1. 正常路径：模板支持现存消息及新任务，不改变 handler 的 payload 结构；外存不因迁移而加载进 Redis。
2. 并发与中断：对结算确认丢失、领取后断连、短租约、旧记录转换竞争、抽样未命中分别设置回归；安全恢复不能触及本地活跃 claim。
3. 管理和兼容：检查重放、清理、终态不可变、旧 owner 迁移、保留命名校验与错误传播；每项问题均需真实 Redis 回归证据。

## 首轮验证后的调整

现有测试使用合法的 `testns:dedup` 队列，说明一律禁止状态名称会扩大兼容破坏。改为注册表上的实际父子状态路径冲突核验，保留此类独立队列；在原子投递前同时核验父子两个方向，管理和消费操作也在写入前核验。不得通过改旧测试名称掩盖接口回归。

## 实施复查补充

- claim token 用于区分 begin 已提交但响应丢失的未准入消息；payload 读取失败及已运行 handler 的尝试不返还预算。
- Lua 在修改状态前同时检查键类型、指标计数格式和动态外存 GC 键类型；最终提交标记只在消息、记录和必要索引写入完成后设置。
- History、Admin 和 Archive 的单键读取改为原子类型/内容快照，避免在线 String→Hash 迁移时的 TYPE/GET 竞态；文本身份按字段定义解析。
- 默认可用时间使用 Redis 时间；客户端时钟超前不能使无显式 not_before 的任务进入延迟队列。
- 回归与三轮修复复查记录见 `docs/dev/PLAN-024-core-reliability-OUTCOME.md`。
